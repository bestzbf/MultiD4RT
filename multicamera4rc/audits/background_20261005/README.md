# Kubric 穹顶监督修复

当前生成器把 HDRI 贴在半径约 40 米的背景穹顶上，标签 0 同时包含穹顶与地面。此前有限正深度全部参与几何、静态轨迹和尺度监督，模型因此拟合出远处的背景墙。

`dense_target_version=2` 在米制参考坐标中使用变换后的世界地面方程，保留 ID>0 的全部物体和 ID=0、距离 z=0 地面不超过 0.05 米的点。筛选发生在场景尺度计算之前，同步更新各项监督与验证掩码。RGB、相机/时间输入、模型权重结构、全像素有效监督和其他数据集的 GT 约定保持原有设计。没有按 p98 或固定距离删除物体。

核查结果：

- [kubric_masks.json](kubric_masks.json)：24 组 C2T12/C3T8/C4T6，8 个场景，37,748,736 个输入像素。
- [variable_masks.json](variable_masks.json)：17 组 C1T16/C1T32/C5T4/C8T6/C10T4，4 个场景，34,603,008 个输入像素。
- 两份核查均逐像素与原始 H5 的 float64 世界坐标计算一致，物体和可信地面全部保留；ray、轨迹、位移、静态、可见性和尺度检查通过。
- [tests.json](tests.json)：服务器 98 项数据/损失/度量/DDP/续训相关测试，以及 3 项切换控制器测试通过。新增测试覆盖倾斜相机、远处物体不被删、无效区域各项损失梯度为零。

复跑入口为 `scripts/audit_kubric_background.py --data-config CONFIG --plan FIXED_PLAN --output REPORT`，使用原始不可变验证计划，且不做网络推理或稀疏点插值。

`scripts/continue_background_recovery.py` 根据 job.json 等待原子检查点，核对代码、证据、PID 启动时间和所属用户后，仅停止记录的训练进程树。切换代码后先在新掩码下重评旧权重，再恢复模型、Adam、数据游标与两 rank RNG；使用 100 步 LR 预热，首段 200 步后验证，后续每 1000 步验证至 50k。非 Kubric 数据的固定指标较新基线恶化超过 25% 时停止并保留检查点。

旧报告与新报告的归一化尺度及有效像素不同，不能直接横比。新策略忽略穹顶目标，不保证旧模型已有的背景墙会立即消失；纯 RGB 推理输出仍需独立评估，不能用 GT 掩码伪装成预测有效性。
